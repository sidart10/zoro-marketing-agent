# Content Writing

Write original content by making three independent choices: **format**, **subject lens**, and
**rhetorical pattern**. This keeps the writing flexible without inventing a separate style for every
possible combination.

## Workflow

### 1. Build the working brief

Infer as much as possible from the request and supplied material:

- **Format:** X short post, X thread, LinkedIn post, newsletter/article, YouTube script, or
  short-form video script.
- **Subject lens:** for example tech productivity, informative tech, product review, AI automation,
  creator business, or a user-defined domain.
- **Rhetorical pattern:** explainer, listicle, tutorial, comparison/review, contrarian argument, case
  study/build log, or narrative lesson.
- **Audience and outcome:** who should understand, believe, feel, or do what after reading/watching.
- **Evidence:** facts, examples, experience, links, transcripts, notes, or saved source material.
- **Voice constraints:** the user's voice, brand voice, desired energy, and explicit exclusions.

Ask one bundled question only when a missing answer would materially change the draft. Otherwise,
choose a sensible default and state it briefly after the deliverable.

Read `references/content-types.md` for the selected format. Read the relevant section of
`references/writing-patterns.md` for the subject lens and rhetorical pattern.

### 2. Make a small source packet

Use the brief first. When connected notes, bookmarks, transcripts, or research are available, select
only the few sources relevant to this draft instead of loading an entire library.

For each factual claim, know whether it is:

- **Sourced fact** — supported by supplied or retrieved evidence.
- **Attributed experience** — supplied by the user or clearly attributed to its source.
- **Inference/opinion** — framed as analysis, not disguised as fact.

Never invent statistics, quotations, product behavior, personal experience, or results. If evidence
is missing, use an honest placeholder, remove the claim, or label it as a hypothesis.

Read `references/corpus-and-voice.md` when using saved creator material, transcripts, bookmarks, or
requests framed as “write like” someone.

### 3. Choose the angle before drafting

Write three private planning lines:

1. **Thesis:** the one idea this piece proves or teaches.
2. **Reader change:** what the audience should understand or do differently.
3. **Progression:** the ordered reasoning that earns that change.

If those lines are vague, the draft will be vague. Tighten them before writing prose.

### 4. Draft to the format contract

Follow the selected contract in `references/content-types.md`. Use one primary rhetorical pattern;
add a second only when it makes the reasoning clearer.

- Open with useful tension, a concrete problem, or a clear promise—not empty suspense.
- Make each paragraph, thread post, or script beat advance the argument.
- Prefer concrete examples, decisions, and tradeoffs over strings of adjectives.
- Let structure create momentum; do not manufacture urgency with hype.
- Make the ending resolve the opening and give the audience a useful next thought or action.

Load examples only when they match the requested format:

- `examples/social-posts.md` — X short post, X thread, LinkedIn post.
- `examples/video-scripts.md` — informative YouTube and short-form scripts.
- `examples/long-form.md` — newsletter/article structure and opening.

Examples demonstrate decisions, not phrases to copy.

### 5. Run the editorial pass

Revise in this order:

1. **Truth:** verify claims, preserve uncertainty, and remove fabricated specificity.
2. **Argument:** ensure the conclusion follows from the evidence and each section earns the next.
3. **Specificity:** replace generic abstractions with an example, mechanism, criterion, or decision.
4. **Voice:** match supplied voice samples and constraints without copying a creator's signature
   wording or persona.
5. **Cadence:** vary sentence and paragraph length deliberately; remove throat-clearing and repeats.
6. **Platform fit:** apply the chosen format's pacing, visual cues, length, and interaction model.
7. **Originality:** remove borrowed catchphrases, recognizable mimicry, and generic AI-writing habits.

Common AI-writing habits to cut unless the voice explicitly calls for them: inflated claims,
one-sentence paragraphs used mechanically, repeated “not X, but Y” constructions, fake quotations,
decorative em dashes, generic rhetorical questions, and an unnecessary closing CTA.

### 6. Deliver the useful artifact

Put the finished draft first. Then include only what helps the user act:

- a title or hook options when requested;
- brief assumptions when a default materially shaped the result;
- source notes for claims that need review;
- placeholders clearly marked for missing proof or personal details.

Do not publish, schedule, or send content unless the user explicitly asks for that external action.

## Quick reference

| User asks for | Format | Common pattern |
| --- | --- | --- |
| “Write a sharp post about…” | X short post | Insight, contrarian, or mini-explainer |
| “Turn this into a thread…” | X thread | Listicle, tutorial, or argument |
| “Write this for LinkedIn…” | LinkedIn post | Insight, framework, case study, or lesson |
| “Write a deep dive/newsletter…” | Newsletter/article | Explainer, argument, case study, or comparison |
| “Script a YouTube video…” | YouTube script | Explainer, tutorial, or review/comparison |
| “Make this a Reel/Short…” | Short-form video script | One insight, quick tutorial, or before/after |

## Common mistakes

- Treating a topic as an angle. “AI automation” is a topic; “automate stable handoffs before fuzzy
  judgment” is an angle.
- Combining format, subject, and pattern into a rigid named style.
- Loading many examples and producing an averaged, generic voice.
- Copying a creator's surface mannerisms instead of understanding the underlying editorial choice.
- Starting with a hook before deciding what the piece can honestly deliver.
- Adding statistics or personal stories because the draft feels insufficiently persuasive.
- Giving every post the same short-line cadence, list structure, or motivational ending.
